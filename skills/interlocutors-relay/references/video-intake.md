# Video and transcript intake

Use this flow when the current relay task includes giving the interlocutor a source video to inspect. The active host retrieves and transcribes through available supported tools; `relay_video.py` only records exact local artifacts, builds existing session requests and keeps delivery/review observations distinct. It is not a downloader, transcriber or claim that every ChatGPT route can inspect video.

1. Inspect source/ad labels **before acquisition**. `plan_video` preserves the source reference, actual observation/evidence and time. Skip known ads before downloading, transcribing or submitting them. If status is unknown, inspect further rather than guessing or requesting another approval already covered by the task.
2. Acquire the non-ad video and inspect it with an available media probe/decoder. `record_video` captures the exact local path, SHA-256, byte size, acquisition and duration provenance. Label playback captures and excerpt offsets accurately. A hash does not establish a playable video or an audio track.
3. Obtain real timestamped transcription output and save it as UTF-8 text/JSON. `record_transcript` binds its file/hash and segments to the selected video bytes, preserves method/source and uncertainty, and validates time ranges. Empty ASR output with unresolved speech is `partial` plus `segments: []` and explicit uncertainty; it is not `no_speech`. Preserve an actual no-text/failure note as the transcript artifact when needed. Never invent dialogue, timings or a successful adapter.
4. `submission_packet` creates the existing `create_session`/`prepare_turn` request pair with the video and transcript attached in that order. Store all returned JSON privately. The helper does not send or replace SessionStore dispatch. Use the existing durable `begin_dispatch` → one supported-tool send → actual `record_sent` or uncertainty/reconciliation flow.
5. Stage exact allowlisted files and observe acceptance. Record each role with `record_delivery(event="accepted"|"rejected", ...)`. Send the generated wording that both files are attached only when that matches the observed attachments. A rejected video needs an honest limitation; any separately chosen transcript/frames fallback must describe what was actually sent and cannot count as original-video inspection.
6. After the real send, record `submitted` with the saved-message reference and only the roles actually present. Attachment acceptance, original video submission and author inspection are separate facts. Do not retry an ambiguous send blindly.
7. Preserve the exact returned response and use `record_review`. A video inspection assessment requires observed acceptance/submission and timestamped visual details from the actual reply. Preserve full/partial/unknown scope. Transcript-only review is useful and must remain labeled as such. Author testimony plus operator observation is not independent backend perception telemetry.

Use [transport recovery](transport-recovery.md) for rejected uploads, exact-path file-picker privacy and a separately journaled failure notice. Local size/hash/decoder checks do not establish successful upload. Verify exact attachment chips and saved delivery after a proposed repair. Label contact sheets as sampled frames at specified timestamps, not original album stills or continuous-video review. Caption lyrics are source text rather than an audio transcript. Probe evidence of no audio track differs from empty ASR output on faint nonzero audio; retain unresolved speech explicitly.

The standalone CLI is `python relay_video.py --request <private-request.json>`. Its JSON envelope is `{"method":"method_name","arguments":{...}}`; later operations take the entire previous `result` record as `arguments.intake`. The public methods are `plan_video`, `record_video`, `record_transcript`, `record_delivery`, `submission_packet`, `record_review` and `inspect_video_intake`. Returned records are copied JSON; save each private checkpoint. Reuse SessionStore for persistence and resumption of the actual message turn.

For the complete input contract, runnable local API example, CLI integration, truthful no-text outcomes and test boundary, open `docs/video-intake.md` from the configured companion runtime root in the private deployment notes. Resolve that runtime location rather than assuming the installed skill has a sibling source checkout. Do not add private source/video/transcript files to public exports. A release must explicitly include this module and guide before claiming packaged support; local source work alone does not update an existing release.
