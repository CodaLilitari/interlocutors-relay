# Creative work without losing the author

The relay supports a creative loop as well as replies: originate an idea, generate candidates, inspect the actual files, explicitly select a bundle, and separately authorize any external action. A tool or reviewer cannot silently choose on the interlocutor's behalf.

## Begin with a usable brief

Record the concept's origin, intended output, source assets and rights status, identity-reference role, what must remain fixed, what may vary, and what must not appear. Keep references and private creative history outside a public code release. A reference image is not automatically an edit target, and a source film still is not automatically cleared for redistribution.

Keep the first batch proportionate to the question. One candidate can test transport; a few genuinely different candidates can test composition. There is no ten-image quota. Generate art without prose when typography needs a separate controlled pass. Use the available supported image-generation/editing tool, not a text description presented as an image.

Assign each actual output a stable candidate ID. Preserve its parent, prompt revision, tool, source-asset IDs and transformation. A new crop, repair, upscale or text overlay produces a new file and candidate; it does not inherit selection invisibly.

## Inspect what actually came back

Record measured MIME type, byte size, dimensions and SHA-256. Report orientation/transparency only when actually inspected; this package's header checker is not a full image decoder or perceptual validator. Requested resolution is not delivered resolution. A preview thumbnail, filename or provider claim is not a full-size visual review.

Open the actual image and check the relevant invariants: recognizability, face and expression, body/hand anatomy, pose, clothing, scene coherence, unwanted objects, other people and text legibility. For video, inspect the relevant motion/audio interval; a still frame cannot validate either. Specialist reviewers advise but do not select a public candidate.

Useful dispositions are SELECT, REVISE, REJECT, HOLD, QUIET, NEED_ATTACHMENT and NEED_CONTEXT. A positive reaction is not an unambiguous selection. Preserve rejected candidates as private process evidence only when useful; do not publish them by default.

## Select the whole bundle

A selected unit comprises the exact caption/text, ordered media metadata and exact alt text. Return the actual image plus caption and alt text through a route that supports the required attachments. Text-only messaging can carry a brief or source description, not a visual-review receipt. A local path written in a message is not an uploaded image.

The core's full-payload digest binds caption, file IDs, bytes hashes, MIME types, sizes, ordering and alt text. The separate private manifest maps those IDs to exact local files. Recheck the files immediately before an authorized attachment operation. A matching digest proves consistency, not ownership, consent, visual quality or delivery.

Caption approval does not approve a later image; image approval does not approve a caption. New bundle bytes need a new revision and the applicable author review. The public software contains no canonical face, private persona, conversation archive or automatic license for user media.

## Publish only under the actual action policy

Generation, file inspection and staging are not publication. Verify exact actor, destination, reply parent, audience and full bundle under the human's current permission policy. Apply the destination's actual rules; this workflow makes no guarantee against platform flags. Perform the authorized action once through a supported interface, inspect the result, and return discrepancies or uncertainty instead of retrying blindly.
